Migration to YukiHook 1.5.x ​

YukiHook has been completely refactored since version 1.5.0, you can read on to see what to pay attention to and what is new.

Notice

The migration documents of the earlier 1.2.x (released in 2023) and 1.3.x (released in 2025) have been removed because they are too old. This document is intended for users updating from version 1.3.x. If you are using an earlier version, please refer to the changelog first to learn the changes of each version.

Version 1.5.x keeps compatible forms for most of the old usages, they are marked as deprecated. You can finish most of the migration by following the hints of the IDE, and these compatible forms will be removed in a future version.

Project Renaming ​

This is the biggest change so far, the project has been officially renamed from YukiHookAPI to YukiHook.

The entry object YukiHookAPI has been deprecated, please migrate to YukiHook.

The following example

kotlin
// Old usage.
YukiHookAPI.encase { ... }
YukiHookAPI.Status.isModuleActive
YukiHookAPI.VERSION
// New usage.
YukiHook.encase { ... }
YukiHook.Status.isModuleActive
YukiHook.VERSION

To stay compatible, the groupId of the dependencies and the package name of the code are still com.highcapable.yukihookapi, you basically don't need to change any import.

Dependency Changes ​

YukiHook is now split into multiple modules, and you need to add a base module to decide which Xposed API to work with.

Old DependencyNew Dependency
com.highcapable.yukihookapi:apiyukihook-core
com.highcapable.yukihookapi:ksp-xposedyukihook-compiler
de.robv.android.xposed:apiyukihook-runtime-xposed82 or yukihook-runtime-libxposed

If you want to keep exactly the same runtime environment as before, choose yukihook-runtime-xposed82. If your target hook framework supports the libxposed API (such as LSPosed), we recommend using yukihook-runtime-libxposed.

If you want to be compatible with multiple base modules at the same time, please refer to Multi-Entry Variants.

YukiHook now uses a BOM to manage the dependency versions in a unified way, please refer to yukihook-bom.

The KavaRef related features have been removed from yukihook-core, for details please refer to About KavaRef below.

About KavaRef ​

In version 1.3.x, YukiHook depended on KavaRef directly and provided KavaRef related functions in PackageParam, now they have been removed from yukihook-core and moved to yukihook-extension-kavaref.

If you use KavaRef in your project, please add this extension module. It does not pass the KavaRef dependencies, so you still need to add KavaRef yourself, please refer to here.

In version 1.3.x, most of the functions below were members of PackageParam and could be used without imports, now you need to import them manually. The functions and classes under ...hook.core.api.reflect also need to be migrated to the new package name.

Old APINew API
MemberResolver.hook and hookAll in PackageParamcom.highcapable.yukihookapi.extension.kavaref.hook and hookAll
String.toClass and toClassOrNull in PackageParamcom.highcapable.yukihookapi.extension.kavaref.toClass and toClassOrNull
VariousClass.toClass and toClassOrNull in PackageParamcom.highcapable.yukihookapi.extension.kavaref.toClass and toClassOrNull
lazyClass and lazyClassOrNull in PackageParamcom.highcapable.yukihookapi.extension.kavaref.lazyClass and lazyClassOrNull
com.highcapable.yukihookapi.hook.core.api.reflect.invokeOriginal and invokeOriginalQuietlycom.highcapable.yukihookapi.extension.kavaref.invokeOriginal and invokeOriginalQuietly
com.highcapable.yukihookapi.hook.core.api.reflect.AndroidHiddenApiBypassResolvercom.highcapable.yukihookapi.extension.kavaref.resolver.AndroidHiddenApiBypassResolver

The following example

kotlin
// Old usage.
import com.highcapable.yukihookapi.hook.core.api.reflect.AndroidHiddenApiBypassResolver
import com.highcapable.yukihookapi.hook.core.api.reflect.invokeOriginal
// New usage.
import com.highcapable.yukihookapi.extension.kavaref.hook
import com.highcapable.yukihookapi.extension.kavaref.invokeOriginal
import com.highcapable.yukihookapi.extension.kavaref.resolver.AndroidHiddenApiBypassResolver
import com.highcapable.yukihookapi.extension.kavaref.toClass

AndroidHiddenApiBypassResolver no longer provides the get function, please create its instance directly.

The following example

kotlin
// Old usage.
resolve().processor(AndroidHiddenApiBypassResolver.get())
// New usage.
resolve().processor(AndroidHiddenApiBypassResolver())

These functions can only be used in PackageParam now, including invokeOriginal, which could be used anywhere in version 1.3.x.

Pay Attention

toClass, toClassOrNull, lazyClass and lazyClassOrNull in KavaRef have the same names as the functions provided by this module, do not import both of them in the same file, otherwise an overload resolution ambiguity will occur.

If you only import these functions from KavaRef, the code still compiles, but they use the ClassLoader of the module when the ClassLoader of the host is not passed, which may cause the Class in the host to not be found.

Entry Changes ​

@InjectYukiHookWithXposed and IYukiHookXposedInit have been deprecated, please migrate to the entry annotation of your base module and YukiHookXposedModule.

The following example

kotlin
// Old usage.
@InjectYukiHookWithXposed
object HookEntry : IYukiHookXposedInit {

    override fun onInit() = configs {
        isDebug = false
    }

    override fun onHook() = encase {
        // Your code here.
    }
}
// New usage.
@YukiHookXposed82Entry
object HookEntry : YukiHookXposedModule {

    override fun onInit() = configure {
        debug = false
    }

    override fun onHook() = encase {
        // Your code here.
    }
}

The parameters of @InjectYukiHookWithXposed changed as follows.

Old ParameterNew Parameter
sourcePathRemoved, the compiler finds the project path automatically
modulePackageNamemodulePackageName in @YukiHookXposed82Entry
entryClassNameentryClassName in both entry annotations
isUsingXposedModuleStatusgenerateModuleStatus in @YukiHookXposed82Entry
isUsingResourcesHookRemoved, Resources Hook is no longer supported

Pay Attention

Entry files are now generated in the build directory for each build variant. Please delete assets/xposed_init, assets/yukihookapi_init and resources/META-INF/yukihookapi_init generated by older versions from your source directory manually, otherwise the build fails.

onXposedEvent and YukiXposedEvent.events are no longer called, please migrate to registerFrameworkEvents provided by the base module and call it in onInit.

The following example

kotlin
// Old usage.
override fun onXposedEvent() {
    YukiXposedEvent.events {
        onHandleLoadPackage {
            // ...
        }
    }
}
// New usage.
override fun onInit() {
    registerFrameworkEvents {
        onHandleLoadPackage {
            // ...
        }
    }
}

For details, please refer to yukihook-runtime-xposed82 → Framework Events and yukihook-runtime-libxposed → Framework Events.

YukiHookAPI.configs has been deprecated, please migrate to YukiHook.configure.

Removed Features ​

The following features have been removed or no longer take effect in version 1.5.x.

  • Resources Hook: resources().hook { ... } has been removed, and the handleInitPackageResources event is no longer called
  • Own reflection API: method { ... }, current(), searchClass and type definitions such as StringClass deprecated since version 1.3.0 have been removed, please migrate to KavaRef, for details please refer to here
  • Old hook style: TargetClass.hook { injectMember { ... } } has been removed, please refer to Hook Usage
  • Use as a hook API: YukiHook.encase(baseContext) is only available in yukihook-runtime-xposed82 and has been deprecated, please use the native API of the hook framework
  • loadZygote: only available in yukihook-runtime-xposed82 and has been deprecated, please move hooks of apps to loadApp and hooks of the system framework to loadSystem
  • TaiChi and Wuji activation checks: TaiChi stopped being maintained on 2024.05.08, YukiHookAPI.Status.isTaiChiModuleActive has been deprecated, and the status of isXposedModuleActive has been moved to isModuleActive, which no longer includes the activation status of the module in TaiChi and Wuji
  • Hook framework type: no longer supported because of dirty state maintenance issues, ExecutorType has been removed and YukiHookAPI.Status.Executor.type can no longer be used, please use YukiHook.Status.Executor.name to get the name of the hook framework
  • Hook related types: YukiMemberHookCreator and its MemberHookCreator, MemberHookCreator.Result and MemberHookCreator.HookCallback have been removed, if you declare these types explicitly in your code, please migrate them to YukiHookCreator.ClassicMemberHooker, YukiHookCreator.ClassicMemberHooker.Handle and YukiHookCreator.ClassicMemberHooker.HookCallback respectively

Project Builder ​

Because the rapid iteration of modern Android development templates has greatly affected project maintenance, the value of YukiHookAPI-ProjectBuilder has gone. This project is no longer maintained and has been officially deprecated, please configure your project manually by referring to Quick Start.

Behavior Changes ​

  • loadApp no longer includes the system framework. Passing android or system to loadApp is treated as loadSystem,
  • and mixing them into multiple package names throws an exception at runtime, please use loadSystem directly
  • YukiHookPrefsBridge.isPreferencesAvailable has been removed, please use isAvailable or isWritable
  • throwToHostOnFailure only applies to the callback it is set on. In version 1.3.x, after setting onFailureThrowToApp
  • on either before or after, exceptions in the other callback were also thrown to the host, if you rely on this behavior, please set it on each of them
  • throwToHost now takes effect in the intercept callback. In version 1.3.x, exceptions set in callbacks such as
  • replaceAny were overwritten by the return value of the callback. intercept now also returns HookCallback,
  • you can use throwToHostOnFailure to throw exceptions to the host instead of calling the original method when they occur
